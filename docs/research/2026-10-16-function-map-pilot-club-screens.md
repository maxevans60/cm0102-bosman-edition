# Function map pilot 2: club_screens.cpp

Date: 2026-10-16. Original: `clean-3968/cm0102.exe` 3.9.68. Research only. The build did not change.

This pilot tests the shortcuts of `2026-10-16-function-map-estimate.md`: a prepared dossier per function, one API request per function through the Message Batches API, and the model chosen by size. Names are first-pass names. Each one rests only on its dossier.

## Method

- Ghidra 12.1.4 headless decompiled all 6,862 game and library functions once (112 failed, these get capstone disassembly).
- A script writes one dossier per function: placement, size, `ret`, strings with addresses, assert line numbers, globals, callers and callees with their source files, pointers from data, and the pseudocode (cut at 2,500 lines). A file summary (all functions of the file with size and first strings) is the shared cached prefix.
- Model by size: up to 20 instructions `claude-haiku-5-5` (effort low), up to 150 `claude-sonnet-5-5` (medium), larger `claude-opus-5-5` (medium). Structured output: name, file, convention, purpose, evidence, confidence.
- Wave 2: the 37 low-confidence names again, with `claude-opus-5-5` at effort high and the wave-1 names of the other functions of this file next to their addresses.
- Blind: the requests contain no names from earlier research.

The file has 132 placed functions and 17 gap functions (149 in total, 73,570 instructions, an average of 494 a function). By model: 30 Haiku, 58 Sonnet, 61 Opus.
