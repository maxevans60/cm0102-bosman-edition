# New competitions: the shared module (0.6.0, owner slice 26)

Date 2026-10-18. Code: `src/recomp_rt/win/season_comps.h` (the interface, read it first) and `season_comps.c`. Evidence: `2026-10-18-new-comps-load.md` (save, load, [0xadadfc], classes, club +0x1db) and `2026-10-18-club-world-idle.md` (how an object waits for a later edition). Users: slices 20, 21, 24, 26, 28 and 29.

## What the module does

A new competition is one that the original has no object for. A slice describes it with one `SeasonCompDef` line in `season_comp_defs` (`season_comps.c`, the slice's own block):

| Field | Meaning |
|---|---|
| `comp` | the `comp` of its rows in the rules table (comp_file `new`), for example `sudamericana` |
| `file` | its name in the logs and the rules report, for example `new_sudamericana` |
| `record` | the long name in the data of the competition record it takes |
| `entry` | the league table entry whose array holds it |
| `make` | the slice's function that makes the object (see "Classes") |

The module then:

1. **Makes the object once per game**, in the `entry` hook of its entry in the first season S from the start season on that the table holds it. Slice 16 runs that hook for the start season with changing rules on or off (in the run to the start date, on the entry's update day, or at the end of the new game), and for later seasons only with changing rules on (Q232). No hook runs in the base game or with `RECOMP_SEASON_CODE=off` (Q152, Q342), and `season_comps_on` is checked again.
2. **Puts it into the entry's array** (`season_change_add_comp`) and into its slot of [0xadadfc] (the daily update 0x5ce060 walks the table, not the arrays; the load doc, section 1, point 5).
3. **Names it**: the record gets the table's name of S through `season_change_rename`, and a later name of the table in the `after` hook, with one news sentence each (Q226, Q238, Q258). The first edition in a later season gets the sentence "The <name> is played for the first time."
4. **Keeps it across a save and a load** (below).

The entry must exist: a national entry needs its nation selected (+0x11c); a continental or world entry needs at least one object of the original (a creator makes none when no nation of its continent is selected, 0x6699d0).

Not the module's: the seasons after the first edition that the table does not hold. The shared rule (lead, 2026-10-18, in `season_comps.h`): a competition that comes back after a gap waits with its year +0x40 at its next edition, as `season_kind_club_world.c` does; only one that never comes back calls `season_change_skip` in a `before` hook (a skipped League class never draws again, 0x92a73d..0x92a74f), the rules of each season (club count, format, places), the club pickers and the rules report lines of the competition.

## The record

Each object needs a club_comp record (0x6b bytes in [0xae23d0]): it holds the name, keys the history, gives the [0xadadfc] slot (by record id, record +0) and gives the save file its name. Version 1 of the module takes a record that the data holds and no object of the original uses. In every Update Team database checked (3.9.68, September 2009, October 2024, December 2025) these are:

| Record | Index | Note |
|---|---|---|
| South American CONMEBOL Cup | 60 | predecessor of the Copa Sudamericana; key id 0x9cf644, no object |
| South American Recopa | 61 | key id 0x9cf648 (matched at 0x60f799), no object |
| CONCACAF Cup Winners Cup | 344 | key id 0x9cf730, no object |
| Afro-Asian Champions Cup | 373 | no object |
| European Cup Winners Cup | see sweep-europe 1.4 (0x9cf6ec) | read only by `Eur_Super_Cup::pick_clubs` in 1999 |

Two defs must never take one record: two objects of one record write one save file (load doc 2.3). A record index must lie below [0xae2378] and outside the last 0x7f club_comp records, which the friendly object uses (load doc 4, point 4; inference). `season_comps_record` finds a record by its name in the data, also after a rename (`season_change_data_name`, a small block of slice 26 in `season_change.c`).

A competition with no spare record (for example a Conference League whose history must not mix with the Cup Winners' Cup, build brief slice 24) needs a new record in the array. Version 1 does not make records: see "Open".

## Classes

A def's `make(d, rec, year, loading)` makes the object in the game's heap: operator new 0x944cf1 with the class size, then the constructor of an original class (thiscall: year, record; `ret 8`), through `rt_callback` with the constructor in `tools/recomp/callbacks.py` (checked bytes). The constructor loads the object's state from its file when one exists (`loading` 1) and else builds a new edition.

Every class of the original except `Conmebol_Liber` picks its clubs from key id globals or fixed lists, not from its record (load doc 5: a second `Conmebol_Merc` invites the same 20 clubs, a second `World_Club_Cup` takes the same two winners). So a def usually needs a vtable copy with its club picker changed: `season_comps_vtable(vtable, slots)` copies a vtable into runtime memory (Cup 40 slots, League 45, sweep-europe 2.2), `season_comps_set_slot` points one slot at a runtime function (`rt_host_fn`). The constructor writes the class's vtable, so `make` writes the copy into object +0 after the constructor. A picker that is a direct call (not a vtable slot) needs a wrap of the original with a test of the object instead. Fields of a class after the base fields are saved only through vtable +0x20 and +0x24 (load doc 2.3); a def that keeps more state saves it there.

A `Conmebol_Liber`-class object takes the clubs whose +0x1db holds its record id (0x4c3fb7); one club holds one value, so a club cannot enter two such competitions in one season.

## Save and load

- **Save**: no change. `key_nation_save_all_comps` 0x6692f0 calls vtable +0x1c of each object of each entry array, and the save packs every `*.tmp` file (0x933610). The file is `<record long name, "/" and "." made "_">_<record id>.tmp` (Cup 0x5210fe..0x521162, League 0x6891ce..0x68923a).
- **Load**: the creators make only the original's objects (`key_nation_create_all_comps` 0x669180 at 0x82c5aa, fixed counts). The module wraps `build_comp_object_table` 0x8386f0. At a load (its call at 0x82c5f6; `season_change_is_creating()` is 0 there), before the original fills [0xadadfc] from the arrays, it makes each def's object whose file came out of the save, with `loading` 1, and adds it to its entry. The constructor reads year and record from the file (Cup 0x520288, 0x5207f3; League 0x6883c3, 0x688541).
- **The save part holds nothing** for the module: the file shows that the object exists. A def that the game never made has no file, because its record has no object of the original. At a load the record already holds the name of the save, so the constructor opens the same file name.
- Inference to check with the first def: the temp files of a game are in the user folder (the `*.tmp` files of a run lie there). The first slice that adds a def runs a save and a load and checks the object, its year and its fixtures after the load.

## Rules for the slices

- Add your def in your own block of `season_comp_defs`, and your constructor and any original function you call to `callbacks.py`.
- Guard every write of your own kinds with a season game test (`season_comps_on`); kinds run for the start season too, so write only real changes.
- One record per def. Say in your doc which record you take.
- The rules report needs to know your object's class: a vtable copy is not in the class table of the build (`make_comp_classes.py`), so the report shows `?` for it. Version 1 gives no fix; the first slice with a def adds the copy's address to the report's class lookup in a small block of `season_report.c` (owner slice 12).
